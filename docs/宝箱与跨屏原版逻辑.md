# 宝箱与跨屏的原版逻辑核对

核对版本：Wuwa Tappo CN 1.0.3。核对日期：2026-10-31。

本文依据仓库中未修改的官方发行文件及当前 macOS 包。宝箱的 `left`、`right` 是原版两个槽位的内部名称，不代表当前布局一定在玩偶左右两侧。

## 结论

- 原版最多两个宝箱槽位。
- **未登录时直接显示两个宝箱入口。点击任一个进入登录选择，不领取奖励、不扣字符、不启动领奖冷却。** 因此看到两个图标不能判断已经攒满两个奖励。
- 已登录后的实际可领取状态由账号数据、服务端时间、字符余额及槽位冷却决定。
- 原版拖动限制在当前屏幕内。切换屏幕走 F10／显示屏幕切换流程，不能用“拖不过屏幕边界”判定切屏实现失败。

## 官方说明与客户端执行的边界

原版“关于”页 `index-BEWn23m-.js` 明确说明：

| 项目 | 官方说明 |
| --- | --- |
| 生成 | 每累计 30 分钟活跃时间生成一个宝箱。 |
| 领取消耗 | 每个宝箱消耗 1,000 字符。领取后相应扣除，并开始下一轮 30 分钟活跃计时。 |
| 上限 | 最多存储两个未领取宝箱。 |
| 满槽 | 两个槽位存满时，活跃计时暂停；领取腾出位置后继续。 |
| 初次奖励 | 首次开箱必得角色，第二次必得配件；拥有角色后，其专属表情才加入掉落池。 |

“活跃时间”的服务端累积算法不在恢复的前端代码中。不能把以上说明改写成“打开应用挂满 30 分钟必定生成”，也不能离线模拟账号中奖或掉落。

## 已登录时图标什么时候出现

依据 `index-pp8VWaUF.js` 的 `Wn`、`Gn`、`Ta`、`Fp`、`Kr`、`Xr`、`zr`、`jr`：

| 字符余额 | 已就绪的宝箱 | 正在冷却的槽位 |
| --- | --- | --- |
| 小于 1,000 | 不显示可领取入口。 | 同样隐藏，即使开启“总是展示宝箱”。 |
| 1,000～1,999 | 最多显示一个，左槽就绪时优先左槽，否则选择右槽。 | 选择的槽位可在悬停或开启“总是展示宝箱”时显示倒计时。 |
| 不少于 2,000 | 两个槽位独立判断，就绪槽位显示宝箱按钮。 | 悬停或开启“总是展示宝箱”时显示倒计时；否则隐藏冷却中的槽位。 |

此处的悬停状态为原版 `T.value`，不是另写一个鼠标计时器。“总是展示宝箱”影响冷却提示的显隐，不等于强制生成奖励，也不跳过字符门槛。

启动／账号状态同步期间，原版会暂时保留两个加载中的按钮；实际按钮由 `kt` 禁用。开箱过程中 `Fn` 阻止重复领取。

## 冷却与领取细节

依据同一文件的 `Vn`、`sc`、`Cp`、`co`、`ic`、`rc`、`pc`：

1. 账号返回 `left_treasure_chest`、`right_treasure_chest`。客户端按服务端时间计算两个槽位各自的剩余时间；登录后的初次计时需要成功同步服务端时钟。
2. 剩余时间小于等于零视为就绪。倒计时向上取整到秒，再显示为 `mm:ss`；最后不足一秒显示 `00:01`。
3. 点击时先检查更新锁、加载状态、是否正在开箱、当前槽位是否就绪。
4. 未登录在此进入登录选择并返回，后续领奖分支不会执行。
5. 已登录先检查至少有 1,000 字符，再提交所选槽位及累计字符数。实际扣除量读取服务端 `click_consume`，还会检查其合法性和余额是否足够。
6. 领奖请求成功返回后，`Cp` 将所选槽位设置为 30 分钟本地单调时钟冷却；另一个槽位不被同时重置。随后按服务端奖励字段处理掉落和背包。

本轮仍排除账号服务接入。macOS 包保留未登录入口，不在本地伪造领奖响应、字符消耗或物品解锁。

## 跨屏核对

`index-pp8VWaUF.js` 的桌宠拖动通过 `So`、`eu` 等位置约束，将玩偶限制到当前窗口／工作区。原版主窗口采用覆盖当前显示器的透明窗口，因此拖到边界不会自然跨到另一屏幕。

`switchDisplayMonitor-B50jXMGD.js` 的 `Aa` 是实际切屏流程：枚举屏幕、准备位置快照、调用 `set_main_window_monitor_bounds`、等待视口尺寸、恢复桌宠布局、同步附属窗口，最后完成输入恢复。只有一块屏幕时明确返回 `no_alternative_display`。恢复后的界面快捷键为 F10，可在设置中改绑；macOS 功能键模式可能要求按 Fn+F10。

用户本次反馈的是“拖动过不去”，与上述边界约束一致，不作为 F10 切屏失败的证据。实体手柄输入已由用户确认正常。

随后已在实际双屏环境完成验收：Mi Monitor 为 1920×1080，内建屏幕为 1512×982，位于主屏左下方，包含负坐标。点击原版“切换屏幕”后，界面屏幕编号从 1 变为 2，主窗口截图从 3840×2160 变为 3024×1964；用户另行确认 F10 可以切换。切屏结果正常。

## 本轮验证与修改范围

新增 [原版宝箱规则测试](../tests/original-chest-rules.test.js)，分别直接执行恢复档和已打包前端中的原版表达式，不重写宝箱业务实现。覆盖：

- 未登录在 0、999、1,000、1,999、2,000 字符下仍有两个登录入口。
- 未登录点击两个入口均进入登录选择，不扣字符、不启动冷却、不请求领奖。
- 已登录字符门槛、一槽／两槽选择、就绪和冷却组合，以及悬停／总是展示的显隐矩阵。
- 单槽 30 分钟冷却、另一个槽位不被重置、到期边界、非法时间戳和最后一秒的显示。

当前包与官方原版的这些规则一致，未发现宝箱业务被适配层改写的差异。本轮修正的是此前将未登录图标称为“已存满宝箱”以及把拖动跨屏当作验收项的解释，保留官方运行行为。

原生 UI 实测：在当前 build 7 中分别点击两个宝箱按钮，均打开“活动需要登录参与，请选择登录方式”窗口；关闭两次登录选择后，信息条计数均保持 1235。未点击任何登录方式按钮，没有执行认证或领取操作。`npm test` 的全部 14 项测试通过，其中 6 项为恢复档与当前包各自的宝箱规则检查。
