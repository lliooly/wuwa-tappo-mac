# 原版玩偶下方信息条

用户要求将 Windows 原版玩偶下方的信息条恢复到 macOS 对应位置。

依据 `index-pp8VWaUF.js` 的 `qy/Uy/Vy/Wy` 渲染结构，以及 `index-C3fG-hsi.css` 的 `.pet-info-container/.pet-info/.pet-toolbar`。原版显示总点击数，不是角色名称。

右侧素材是相邻素材库 `assets/界面/原版/pet-info-setting.png`，86×45，SHA-256 `15ffd6730f85604aea00c1f707cf6627e082cad49321408942343412f11eb200`，与原版 `.pet-toolbar` 内嵌 PNG 完全相同。构建读取 `data/files.json` 校验并拷贝。`pet-info-container.png` 虽然是整条背景图，但主桌宠原版这个组件未直接使用它，不能仅凭名称替换。

原版按 200px 角色画布布局：条容器宽180、高32，向上重叠21，右对齐，总占高211。右侧工具图61×32、不收缩；左侧默认宽136，在 flex 中收缩为121，右边距-2。文字18px、加粗、左内边距18，颜色#8e5e43，底色#fdf9ed，左圆角。整个组件位于角色后方。macOS 统一放大1.2倍：角色仍240×240，窗口扩大为240×253.2，不能将角色拉伸到新窗口高度。右侧38×32区域为菜单入口。

实现采用原版右侧 PNG 和原生绘制的数字底色；原版 WOFF2 未注册到 AppKit，本阶段数字用系统粗体替代，非字体像素级复刻。右侧入口打开当前原生菜单，暂未实现 Windows 的完整设置面板。

数字来自本机累计操作数，不伪装官方账号总数：键盘在有效释放时加1（重复按下、孤立释放不计）；鼠标在按下时加1；修饰键沿用当前键盘适配器。存入应用 UserDefaults 的 localClickCount，启动恢复。菜单栏的原始事件数量与该数字分别维护。暂未接官方账号、服务端合并或手柄计数。

验证：构建、codesign校验、原生smoke-test和原生视图导出图检查；素材哈希由构建时索引校验。原生视图导出是程序自身离屏绘制，不启用视觉伴侣或浏览器。

验收结果：构建及签名校验通过，8项既有测试通过，原生smoke-test通过。已导出并目视检查240×253.2pt原生视图：信息条位于角色下方，原版右侧素材完整，角色比例保持不变，分组阴影无拼接线。导出文件为build/pet-info-preview.png。
