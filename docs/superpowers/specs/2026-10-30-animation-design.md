## 身体状态

初始动作 `A=1`，下次方向 `Ll=left`。`Xd` 返回当前方向后将下次方向翻转；`Bl(left)=2`、`Bl(right)=3`。`Yo` 调用 `Xd → Ul`，并向房间逻辑传递方向。

| 事件 | 行为 |
| --- | --- |
| 首次拍击 | 身体 2，下次改为 right |
| 后续拍击 | 身体 3/2 交替，与输入键位及鼠标按钮无关 |
| 拍击超时 | `Ul` 取消旧超时，新建 220 ms 超时，恢复身体 1 |
| 输入释放 | `Wl` 立即恢复身体 1；不重置交替方向，也不取消旧拍击超时 |
| 长按 | 同一键的重复 press 被过滤，不自动连拍，220 ms 后仍恢复身体 1 |
| 多键 | 每个首次 press 都拍击；任一已记录键 release 就恢复身体 1，不等待其他键 |

快速连续输入会重设 220 ms 超时。通常打字显示 `1→2→1→3→1`，紧密按下多个不同键可显示 `2→3→2`。

## 输入与计数边界

`Uc` 用 `qr` 集合过滤重复 key press；先记录键，再检查强制更新锁，未锁时触发拍击。`Vc` 删除键；不是已记录的释放则忽略；未锁时正常键在释放时计数，并回待机。

`mouse-button` 的 press 在常规路径中计数并拍击，release 回待机；鼠标移动不触发拍击。原版右键菜单打开、菜单吞掉的左键操作及强制更新锁会抑制部分输入，必须由窗口/输入适配器处理，不能把合成事件和原生事件同时投递导致重复拍击。

`global-clap-mouse` 与 `gamepad-button-press` 计数并拍击，无对应释放时依靠 220 ms 超时复位。鼠标和手柄与键盘共享本地交替方向。

F5 是原版 Windows 刷新特殊分支：网页 fallback、快捷键占用和约 800 ms 刷新限流会影响计数时点。它不是普通拍击规则，第一阶段不接入刷新命令，不将其转为 macOS 全局快捷键。

动画只输出状态；键盘的有效 release 可作为计数输入，鼠标/手柄在有效 press 计数。持久化、服务端同步和房间发送均由独立订阅者承担，不能用渲染次数作为点击次数。

## 头部与眨眼

初始 `S=1`。主界面启动后创建 5000 ms 周期，回调令 `S=2`，250 ms 后恢复 `S=1`。不是随机间隔，不因输入而重启，身体与头部可同时变化。计时器是调度目标，不承诺系统繁忙或后台限流时精确到毫秒。原版强制更新锁不暂停这条眨眼定时器。

## 配饰、素材与合成

原版配饰 `_n` 解析单张佩戴图片；没有配饰眨眼帧或配饰独立动画定时器的证据。本阶段配饰静态，不添加随眨眼隐藏、换图或弹跳的自创动作。

按头、身体、配饰顺序绘制：头身 z-index 同为 2，身体在 DOM 中后出现；配饰 z-index 为 3。所有图片保留完整透明画布，原版显示基准为 200×200 CSS px，不裁透明边、不各自居中、不按原图像素尺寸原样摆放。

角色读取同一条目的 `files.head1/head2/body1/body2/body3`；配饰读取 `files.image`，图鉴读取 `files.atlas`。用 `type + officialFilename` 查映射，不靠拼接猜路径。同名内置与远端角色不能混搭。

`getUserAccessoryOffset` 优先用当前角色的素材元数据 `offset_x/offset_y`；角色元数据不存在才回退到用户角色 `x/y`。偏移只作用于配饰，不能使用配件自身元数据，也不能把 `my_offset_*` 混入。统一缩放整个 200 px 舞台，使偏移与角色一起缩放。

未找到条目、分层缺失、图片加载失败须明确显示错误，不以完整图、图鉴图或其他角色图静默替代。预览预加载五张角色分层及配饰，成功后再启动动画。

## 表情与联机行为

表情独立于眨眼和配饰。选中表情后创建气泡实例，使用 `files.image`，原版 CSS 为 1 s 上浮淡出，结束移除；不替换头部。

远端 `desktopState=left/right` 分别映射身体 2/3，重设 220 ms 复位；`idle` 立即复位并清理该玩偶超时。远端明确方向不消耗本地交替方向。

每轮主眨眼还调用 `fh` 给房间玩偶分批眨眼：候选为 dockVisible、角色非空且不是自己。人数 ≤25 时全选；26–50 时每轮选 ceil(n/2)；>50 时选 ceil(n/4)。轮转起点为 `Rc * batchSize % n`；启动间隔 `max(20,min(80,floor(2000/batchSize)))` ms，闭眼 250 ms。执行时再次检查可见性和角色。移除玩偶应清理其定时器。

以上表情与房间行为在本阶段归档；第一阶段交付本地玩偶及远端明确方向入口，不实现网络、房间批量调度或表情菜单。后续按已记录规则接入，不宣称当前已支持。

## 模块边界与本阶段交付

1. `src/animation/pet-animation.js`：身体/头部独立状态、键盘去重、输入接口、定时器生命周期；可注入时钟，无 DOM、账号或素材依赖。
2. `src/assets/appearance.js`：按目录索引解析角色和配饰，输出按绘制顺序排列的图层及偏移；缺失即报错。
3. `src/render/pet-view.js`：固定坐标舞台，统一缩放，只消费图层，不监听输入、不计数。
4. `preview/`：本地浏览器验证入口，只接收该页面输入，明确不等于 macOS 全局监听或悬浮窗。
5. `scripts/preview-animation.py`：仅在 loopback 提供应用模块、预览和素材仓库的必要目录，不公开 Windows 样本及整个用户目录。

锁状态由输入适配器设置；失焦/权限中断时适配器调用 `resetInput` 清理可能遗留的键，不合成计数。该恢复接口是移植边界，不是声称原版有同名行为。销毁时清理全部定时器和监听。

## 实施与验证

顺序：规格归档 → 独立动作模块 → 素材与渲染模块 → 本地预览 → 行为测试和预览检查。

自动测试使用假时钟覆盖：220/250/5000 ms 边界、交替不因 idle 重置、连击重设超时、长按去重、多键释放、锁状态、眨眼与拍击并发、重复启动及销毁；素材检查覆盖真实 catalog、配饰字段与角色偏移、缺失分层明确失败。

人工预览检查：正确叠层、眨眼与拍击、更换角色/配饰、透明画布与缩放、失焦后无遗留按键。macOS 全局输入、权限、透明悬浮窗口和原生游戏全屏兼容性属于下一阶段，需单独实现与实机验证。

计时器调度限制参考：[MDN setTimeout](https://developer.mozilla.org/en-US/docs/Web/API/Window/setTimeout)。原版行为结论均以本地发行文件为依据。
