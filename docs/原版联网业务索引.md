## 认证、错误与重试

`Request` 默认超时 10 秒，以 `Authorization: Bearer …` 携带业务会话。请求前调用原版 `renewTokenBeforeRequest`，登录和续期自身跳过该步骤以避免递归；并发续期共享 `renewInFlight`。续期只有在返回数据为 `true` 时延长本机会话时间，普通网络失败不会当作续期成功。

业务成功码为 `0` 或 `200`。`10002`、`10003` 会清除认证并调用原版退出逻辑；HTTP 401／403 也映射到认证失效处理。维护状态交给原版维护页，由宿主提供窗口和主桌宠隐藏能力。

同一路径的在途请求由原版请求锁阻止重复提交。仅请求配置显式带 `reload`、尚未重试且不属于认证错误时，失败分支才重试一次；本索引的配置与图鉴读取设置了该选项。开箱、合成和兑换包装函数没有设置 `reload`，不会通过这一层自动重发。服务端超时后的实际消耗不能凭客户端失败提示判断。

## 房间与累计计数

来源为 `index-pp8VWaUF.js` 的房间状态机，使用 Engine.IO 3／Socket.IO。macOS 的 `OriginalSocketBridge.swift` 和 `original-adapter/socket.js` 只承载传输，继续使用原版消息、ACK 和重连流程。

| 消息 | 原版用途 |
| --- | --- |
| `cr` | 上报待确认点击并处理确认 |
| `rm` | 进入及恢复房间 |
| `rd` | 请求／接收成员外观快照 |
| `rc` | 桌宠动作及外观变化分发 |
| `re` / `ru` | 发送表情／接收远端表情 |
| `rj` / `rl` | 成员加入／离开；`rl` 也用于主动离房并等待 ACK |
| `ro` | 成员离线，隐藏对应远端桌宠 |
| `rs` | 房间解散通知 |
| `fd` | 服务端强制断开及清理 |

离房必须等成功 ACK 或对应解散通知后清理房间状态，再连接大厅；等待超时不会伪装成功。重连仍由原版网络状态和重连定时器控制。实际双向进房、动作、表情、换装、退出与解散已由用户验收，本轮不再重复。

## 平台边界与剩余证据

macOS 已提供 Keychain 会话共享、点击持久化、登录窗口、维护窗口、原生 WebSocket 及跨窗口事件。Windows 更新流程和主程序遥测保持关闭。公开配置、素材和图鉴不能代替账号库存授权。

合成与兑换已获用户补测反馈正常，但用户未逐项说明合成模式、材料和奖励明细。UID 独立验证码登录已实测成功；真实认证失效／服务端强制断开尚缺对应运行证据。保留原版分支并明确记录限制，不为补齐记录而重复发短信、消耗物品或伪造服务器结果。顶栏单色图标属于另一个待确认的界面修改，不包含在本次联网收尾提交中。
