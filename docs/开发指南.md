# 开发指南

应用使用 Windows CN 1.0.3 的恢复前端，配合 Swift 原生宿主运行。构建步骤见 [README](../README.md#从源码构建)。

## 目录

```text
父目录/
├── wuwa-tappo-assets/       # 固定素材快照
└── wuwa-tappo-mac/
    ├── native/             # AppKit、WKWebView、输入、窗口和会话
    ├── original-adapter/   # 原版命令、事件和网络适配
    ├── recovered/          # 原版前端、恢复清单与分析
    ├── assets/             # 素材符号链接及来源索引
    ├── src/、panel/、preview/ # 早期手写实现
    ├── scripts/、script/   # 构建、检查及恢复工具
    ├── tests/
    └── docs/
```

素材库固定提交为 `3b23b04468174fd1329473c64e2a4254999bb819`。保留两个仓库的相对位置与符号链接。构建时复制所需资源，生成的应用可独立运行。

主程序版本为 1.0.3，本地旧安装器为 1.0.2。版本依据见 [恢复分析](../recovered/wuwa-tappo-cn-1.0.3/ANALYSIS.md)。Windows 二进制和 IDA 数据库仅用于历史恢复，日常构建无需这些文件。

## 依赖

| 用途 | 要求 |
| --- | --- |
| 运行 | Apple Silicon，macOS 13+。 |
| 构建 | Xcode Command Line Tools 或 Xcode，Python 3.9+。 |
| JS 测试 | Node.js 22+，无 npm 安装依赖。 |
| 素材恢复与图片检查 | Python 3.11+，依赖见 `requirements-art.txt`。 |

Swift 使用系统 AppKit、WebKit、JavaScriptCore、GameController 和 ServiceManagement。原版前端的第三方库已打包在发行文件中，来源见 [第三方说明](../THIRD_PARTY_NOTICES.md)。

安装素材工具依赖：

```sh
python3.11 -m venv .venv
.venv/bin/python -m pip install -r requirements-art.txt
```

可使用本机已安装的 Python 3.11 或更高版本替换示例命令。

## 版本与签名

`package.json` 的 `version` 跟随所用 Windows CN 主程序，`macosBuild` 为独立递增的 Mac 构建号。构建脚本从这里生成 Info.plist，包检查核对两者一致。

```sh
python3 scripts/build-macos.py
```

生成 `dist/Wuwa Tappo.app` 和 `dist/Wuwa-Tappo-mac-arm64.zip`，默认使用 ad-hoc 签名。指定本机已有身份：

```sh
WUWA_SIGN_IDENTITY='本机代码签名身份' python3 scripts/build-macos.py
```

该命令不执行 Apple 公证。重签后，系统可能重新要求输入监控或钥匙串授权。

重建并打开设置面板：

```sh
./script/build_and_run.sh --settings
```

脚本先等待旧实例保存退出，再替换应用包。

## 检查层次

```sh
# 源码检查，需要相邻素材库
python3 scripts/check-repository.py
node --test tests/animation.test.js
python3 scripts/verify-click-store.py
python3 scripts/verify-session-store.py

# 完整检查，先构建应用
npm test
python3 scripts/verify-original-port.py
python3 scripts/verify-package.py
python3 scripts/verify-standalone.py
```

源码检查覆盖符号链接、恢复文件哈希、版本来源、Python／JS 语法和文档链接。Swift 检查使用隔离偏好与临时 Keychain 项，验证计数迁移和会话持久化。

完整 JS 测试执行原版及包内函数，覆盖动画、宝箱、计数确认、认证续期、预设和 WebSocket。包检查核对签名、版本、ZIP 内容和执行权限。独立运行检查复制应用到临时目录，以隔离标识启动并检查五个原版页面，结果写入 `build/`。

CI 在 Linux 和 macOS 上执行源码、基础动画及 Python 图片解码检查；macOS 另执行构建、完整 JS 测试、原档、包内容与原生存储检查。系统交互与在线业务的实机结果见 [验收记录](最终验收结果.md) 和 [在线功能记录](在线功能验收.md)。

Dependabot 每周一北京时间 09:00 检查 GitHub Actions 与 Python 依赖，配置位于 `.github/dependabot.yml`。Actions 使用完整提交 SHA 固定版本；合并依赖更新前查看 CI 结果。

## 调试

```sh
# 离线启动
open -n 'dist/Wuwa Tappo.app' --args --offline

# 打开登录窗口，输出在线状态
./script/build_and_run.sh --online-check

# 打开设置，观察房间与点击确认
./script/build_and_run.sh --native-check

# 独立检查维护页
python3 scripts/verify-maintenance.py
```

正常启动使用官方 HTTP 与原生 WebSocket，`--browser-socket` 用于比较浏览器传输。在线诊断写入 `build/online-state.json`；普通启动不生成该报告。日志位于 `~/Library/Logs/Wuwa Tappo/`。

实际输入采样：

```sh
open -n -W 'dist/Wuwa Tappo.app' --args --check-input --input-report "$PWD/build/original-input-sample.json"
```

采样 60 秒，报告事件数量与计数变化。输入监控权限需授予应用包。

早期手写界面通过 `--legacy-ui` 运行，`npm run preview` 启动浏览器动画预览。实现依据保留在 [历史设计记录](superpowers/specs/README.md)。
